# ZFP-0006: 项目初始意图与按日期记录的演进

## 摘要

用单个 `EVOLUTION.md` 保留项目初始意图与后续变化，提供可复制的文档示例和
`zendev evolution check` 校验。使用者通过编辑器阅读、追加和修正文档，Git
保留修改历史；工具只负责检查记录结构。

## 动机

`SPARK.md` 记录了项目最初的想法，但随着目标变化，只维护最新表述会覆盖
项目为什么转向的线索。单文件能够保持连续阅读，日期标题帮助使用者定位历史。
编辑器与 Git 已能完成文档读写和版本管理，无需为这些操作维护另一套命令、
写入锁或冲突处理。这类结构校验属于 zendev 的仓库文档工作流。

## 设计

文档以 `# 项目演进` 开始，首先且唯一包含非空的 `## 初始意图`。
初始意图自由书写，可包含内部小节，不要求追溯起始日期。
后续用 `## YYYY-MM-DD` 记录真实日期，每天一节、日期唯一、时间正序。
每一天依次包含非空的 `### 触发`、`### 变化`、`### 理由`。
没有日期记录的文档也合法。结构标题使用顶层 ATX 形式，代码块、HTML 注释、
列表和引用中的标题不参与结构识别。初始意图和三个固定小节需要正文，
仅有空白、注释或下级标题不算非空正文。

使用指南提供可直接复制到 `EVOLUTION.md` 的示例。使用者在编辑器中追加或修正
对应日期的三个小节，再运行唯一的命令：

```shell
zendev evolution check
```

`check` 默认读取当前目录的 UTF-8 文件 `EVOLUTION.md`，支持 `--file PATH`，
不向上搜索。它验证全文，诊断带文件路径与行号；成功或失败都不修改文档，
也不创建锁、索引或其他辅助文件。同一天的多次变化由使用者整理在同一节中，
Git 保留修改历史与协作冲突。

退出码：成功为 `0`，文档结构校验失败为 `1`，
用法、缺失目标、I/O 或 UTF-8 解码失败为 `2`。
可选的 `zendev-evolution-check` prek hook 调用同一校验入口。
独立组件 `zendev-evolution` 提供等价的 `zendev-evolution check`；完整工具包
硬依赖该组件。不依赖 proposal 的配置、关系图或私有实现。

## 兼容性

这是新增功能，不批量改写已有 `SPARK.md`。迁移时只根据可确认的材料恢复起点与
转向，不把当前目标当作初始意图，不虚构缺失日期。首版不提供编号、frontmatter、
主题、额外索引、专用配置、自动摘要、JSON 输出或文档读写命令。
不提供 `init`、`list`、`read`、`write`、`--replace` 或标准输入入口。
提案与实现仍可通过普通链接作为演进记录的依据。

## 验证

通过实际 CLI 子进程验证默认路径、指定文件、诊断与退出码。覆盖起点缺失、重复、
错位、空正文，日期非法、重复、乱序，固定小节缺失、重复、顺序错误或为空，
以及代码块、HTML 注释和嵌套结构中的伪标题。验证指南示例可通过校验，
失败时原文保持不变且不生成辅助文件。
安装独立组件及完整工具包的 wheel 后验证入口，按仓库规范完成静态检查与文档构建。
