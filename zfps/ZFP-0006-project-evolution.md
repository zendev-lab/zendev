# ZFP-0006: 项目初始意图与按日期记录的演进

## 摘要

新增独立组件 `zendev-evolution`，通过 `zendev evolution` 和
`zendev-evolution` 验证、阅读和编写单个 `EVOLUTION.md`。初始意图独立保留，
后续变化按日期组织，不引入条目编号或额外事实源。

## 动机

`SPARK.md` 记录了项目最初的想法，但随着目标变化，只维护最新表述会覆盖
项目为什么转向的线索。单文件能够保持连续阅读，按日期定位与写入则让使用者
不必每次处理完整历史。这类工具属于 zendev 的仓库文档工作流。

## 设计

文档以 `# 项目演进` 开始，首先且唯一包含非空的 `## 初始意图`。
初始意图自由书写，可包含内部小节，不要求追溯起始日期。
后续用 `## YYYY-MM-DD` 记录真实日期，每天一节、日期唯一、时间正序。
每一天依次包含非空的 `### 触发`、`### 变化`、`### 理由`。
没有日期记录的文档也合法。结构标题使用 ATX 形式，代码围栏中的标题不参与识别。

所有命令默认使用当前目录的 `EVOLUTION.md`，支持 `--file PATH`，不向上搜索：

- `init --from PATH`：从初始意图正文创建文件，拒绝覆盖。
- `list`：列出起点和日期及其行号。
- `read`：默认输出初始意图与最近一天；无日期记录时只输出起点。
- `read DATE` 或 `read --origin`：分别只读取指定日期或初始意图，二者互斥。
- `write DATE --from PATH`：从三个固定小节的正文新增日期，按时间插入。
- `write DATE --from PATH --replace`：显式替换已有日期，不隐式创建缺失日期。
- `check`：验证全文，诊断带文件路径与行号，不修改文档。

`--from -` 从标准输入读取。`write` 要求已初始化的文档。
新增已有日期、替换不存在日期均失败。写入前校验原文和输入，保留其他章节原文，
使用独占的临时写入锁、保存前快照检查和原子替换。锁冲突或检测到外部修改就失败；
外部编辑器不受 CLI 锁约束，快照检查不承诺通用文件系统事务。
初始意图通过普通编辑器修正，由 Git 保留历史。

退出码：成功为 `0`，文档或输入内容校验失败为 `1`，
用法、缺失目标、I/O 或并发写入冲突为 `2`。
可选的 `zendev-evolution-check` prek hook 调用同一校验入口。
组件独立安装，完整工具包硬依赖该组件；不依赖 proposal 的配置与关系图机制。

## 兼容性

这是新增功能，不批量改写已有 `SPARK.md`。迁移时只根据可确认的材料恢复起点与
转向，不把当前目标当作初始意图，不虚构缺失日期。首版不提供编号、frontmatter、
主题、额外索引、专用配置、自动摘要、删除命令、编辑器调用或 JSON 输出。
提案与实现仍可通过普通链接作为演进记录的依据。

## 验证

通过实际 CLI 子进程验证初始化、默认和指定读取、日期目录、标准输入、新增与
显式替换及退出码。覆盖起点缺失、重复、错位、空正文，日期非法、重复、乱序，
固定小节缺失、重复、顺序错误或为空，以及代码围栏中的伪标题。
并发写入和外部编辑测试验证冲突失败、原文保留与未修改章节保持不变。
安装独立组件及完整工具包的 wheel 后验证入口，按仓库规范完成静态检查与文档构建。
