# ZFP-0008: 提案直接引用与依赖顺序

## 摘要

为提案关系增加两个默认关闭的仓库策略：正文引用必须显式声明直接依赖，以及依赖
只能指向编号更早的提案。两者复用现有 `graph.requires_field`，不改变其他仓库的
关系语义、文档格式或索引格式。

## 动机

现有关系校验能发现不存在的目标、自引用和环，但不能发现无环的向后编号依赖，
也不能发现正文引用了没有申报的前提。MoonSmith 已选择按编号组织提案依赖，并
要求只有直接声明后才能引用。把检查放在通用工具中，可避免消费仓库维护另一份
Markdown 扫描与关系规则。

[ZFP-0005](./ZFP-0005-proposal-repairs.md) 规定语法感知的正文校验与无环关系，
尚未规定这两项可选策略。本提案只记录这项增量公共配置，不扩展提案生命周期。

## 设计

在 `[proposal.graph]` 中新增两个布尔配置，默认均为 `false`：

- `require_declared_references`：引用同一提案仓库内其他编号文档时，目标必须出现在
  `requires_field` 指定的元数据数组中。传递依赖、`supersedes` 或其他关系不代替
  直接声明；自身引用不产生依赖要求。
- `requires_earlier`：该依赖字段中每条边的目标编号必须小于源编号。按编号比较，
  不读取创建日期或 Git 提交时间；未编号草稿仍检查引用声明，但不推断其顺序。

启用任一策略都必须配置 `requires_field`。错误类型与缺少字段角色属于配置错误，
沿用退出码 2；不合规引用和依赖属于验证错误，沿用退出码 1。

引用取自 Markdown 解析事实：普通正文中的规范编号、内容恰好为单个规范编号的
行内代码，以及指向已发现提案文档的本地链接（包括片段和引用式链接）。链接以
实际目标为准，标签不再单独推断另一个目标。外部链接及其标签、代码块、复合代码
片段、HTML 注释不产生提案依赖。相同前缀但不存在的正文编号仍报告缺失目标。
配置前缀和编号宽度决定规范编号，不扫描其他项目的前缀或猜测自然语言。

检查覆盖配置发现的提案文档，不把索引、路线图等导航文件当成提案正文。诊断指向
引用或依赖声明的位置，分别使用 `proposal.reference.undeclared-dependency`、
`proposal.reference.missing-target` 和 `proposal.graph.forward-dependency`。
现有自边、缺失目标、环与 Schema 诊断继续有效。

`check --fix` 不根据正文自动增加依赖，也不删除引用或重新编号。声明依赖是作者
决定；作者可以补声明、修正文，或调整提案的设计前提。共享 Markdown 层只提供
文本、代码和链接上下文，前缀识别和依赖判断仍归 proposal 所有。

## 兼容性

未启用策略的仓库行为不变。启用策略前，消费仓库需补齐真实直接依赖并修正向后
引用；不自动展开传递依赖。元数据仍支持现有整数或规范编号字符串，索引沿用
[ZFP-0004](./ZFP-0004-numeric-proposal-index.md) 的数字引用格式。

当前统一配置与包边界沿用 [ZFP-0006](./ZFP-0006-domain-architecture.md)。本提案
不恢复旧配置载体，不发布新的包，也不要求所有消费仓库采用相同的治理策略。

## 验证

行为测试区分已声明、未声明和仅传递可达的引用；覆盖普通正文、单编号行内代码、
本地文件与片段链接、引用式链接，以及自身、外部标签和代码示例等排除情形。
无环的向后依赖必须失败，较早编号依赖必须通过，策略关闭时保留原行为。
验证未知编号、未编号草稿、非法配置、只读检查与修复不擅自补依赖，并运行仓库
完整检查。消费端在固定工具版本下用同一配置执行本地命令和提交钩子。
